# 同一篇论文的直接总结与插件精读

这次对照只回答一个问题：同一个模型读 Wei 等人论文的同一份文本，两份笔记各自保住了哪些事实，读者要花多久才能找到依据？样本固定为 arXiv:2201.11903v2。脚本接受该版本的 PDF，检查 SHA-256，使用 Poppler 提取全部 24 页，为每页加上 PDF 物理页序。两组共用这一次提取的文本。双栏排版或表格提取可能有误，评审以 PDF 为准。[原论文](https://arxiv.org/pdf/2201.11903v2)

在仓库源码根目录运行。需要 Node、Poppler 的 `pdftotext` 和一个全新的输出目录。下面第一条命令下载论文，第二条只准备输入和提示，不调用模型。

```sh
curl -fL https://arxiv.org/pdf/2201.11903v2 -o paper-v2.pdf
node benchmarks/paper-pair/run.js paper-v2.pdf e2e-artifacts/paired-prep --prepare-only
```

真实运行使用 DSH headless、pnpm 和环境中的 `DEEPSEEK_API_KEY`。使用与仓库 E2E 相同的 DSH 版本和模型配置。默认请求 `deepseek-v4-pro`，可用 `E2E_MODEL` 选择两组共用的模型。插件从当前源码打包，两组分别开启新会话。运行会产生模型费用。

```sh
node benchmarks/paper-pair/run.js paper-v2.pdf e2e-artifacts/paired-live
```

- **直接总结**把提取的全文放进一次任务，请模型直接输出笔记。出现工具调用会使本组失败。
- **插件精读**把同一文本作为本地论文交给精读工具，使用简洁模式、800 词下限和最多 4 块。脚本核对实际工具参数、成功返回值和落盘笔记。两组都要求英文、相同四个内容部分及相近篇幅。四块是上限，800 词是目标下限，实际篇幅可能不同。
- **组织者**保留 `organizer/`。其中有原始提示、输入文本指纹、模型标识、宿主版本、候选包指纹、各组从启动任务到进程退出的耗时、笔记和 A/B 对应关系。耗时包含宿主启动和工具开销，安装和 PDF 转换不计入。供应商若只提供模型别名，请注明运行日期，跨日期的同一别名可能对应不同模型。
- **评审者**只收 `review/` 和原论文，对照表逐项评分，提交后再揭晓对应关系。文件名随机分配，两份正文都保留原貌，格式或质量提示有可能让人猜到来源。

某一组失败时，本次运行没有可供比较的一对笔记。保留失败记录，已成功的组仍在 `organizer/`。下次用新的目录运行。公布结果时列出 A/B 原稿、每项判断、引文核查和各组耗时；单篇的一次运行只说明这个样例的情况。
